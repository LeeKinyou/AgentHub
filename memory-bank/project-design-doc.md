> 文档版本：v1.0
> 最后更新：2026-05-27
> 角色定位：基于 IM 聊天范式的多 Agent 协作平台

## 一、业务定位与核心价值

### 1.1 产品定位

AgentHub 是一个**以即时通讯（IM）聊天为核心交互范式的多 Agent 协作平台**。

与传统 IDE 或低代码工具不同，AgentHub 将复杂的软件构建过程封装进人们最熟悉的对话界面。用户无需理解 "prompt engineering"、"pipeline"、"workflow orchestration" 等底层概念——他们只需要像在微信群里聊天一样，发送一条消息、@ 一个智能体，就能完成从需求描述到网页部署的全流程。

### 1.2 核心价值主张

| 维度 | 价值 |
|------|------|
| **低门槛** | 零代码基础用户也能通过自然语言描述需求，平台自动完成架构选型、代码生成、调试与部署 |
| **多智能体协作** | 不同领域的专家 Agent 各司其职，由主编排器统一调度，模拟真实团队协作 |
| **即时可见** | 所有产出物（代码、网页、部署链接）均以内联卡片形式直接呈现在聊天流中，所见即所得 |
| **上下文连续** | 对话历史与 Pin 机制确保长期任务不断线，跨会话可追溯 |

### 1.3 典型用户旅程

```
用户新建对话
  → 输入："帮我做一个个人简历网站，风格偏极简"
  → 系统自动匹配 Orchestrator Agent
  → Orchestrator 拆解任务，@ 前端工程师 Agent 生成页面骨架
  → @ UI 设计师 Agent 优化视觉样式
  → @ 部署 Agent 一键发布预览链接
  → 用户在聊天流中看到代码 Diff、网页预览卡片、部署状态卡片
  → 用户点击 "Apply" 应用修改，或点击预览链接查看成品
```

## 二、核心交互范式演进

### 2.1 单聊模式（Single-Agent Chat）

#### 场景定义

用户与**单个特定专家 Agent** 进行定向深度对话。适用于需求明确、领域单一的任务。

#### 交互逻辑

```
┌─────────────────────────────────────────────┐
│  用户                                       │
│  ┌───────────────────────────────────────┐  │
│  │  消息输入区                            │  │
│  │  "用 React + TailwindCSS 搭建一个     │  │
│  │   Dashboard 布局"                     │  │
│  └───────────────────────────────────────┘  │
│              │                               │
│              ▼                               │
│  ┌───────────────────────────────────────┐  │
│  │  专家 Agent（前端工程师）              │  │
│  │  ─ 流式输出思考过程                    │  │
│  │  ─ 生成代码 Diff 卡片                  │  │
│  │  ─ 生成网页预览卡片                    │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

#### 关键行为

1. **Agent 选择**：用户可在对话创建时选择目标 Agent，或在对话中通过 `/agent` 指令切换。
2. **流式回复**：Agent 以打字机效果逐步输出内容，包含自然语言解释与结构化产物卡片。
3. **单点深入**：适合对某一专业领域进行连续追问与迭代优化。

### 2.2 群聊模式（Multi-Agent Chat）

#### 场景定义

一个对话中包含**多个 Agent**，由主编排器（Orchestrator）统一调度。适用于跨领域、多步骤的复杂任务。

#### 完整产品逻辑

```
用户发送消息
       │
       ▼
┌──────────────────────────────────────────────────────┐
│              Orchestrator Agent（主编排器）            │
│  ─────────────────────────────────────────────────── │
│  1. 意图识别：解析用户自然语言，提取核心需求           │
│  2. 任务拆解：将需求分解为可执行的子任务               │
│  3. 角色分配：根据子任务类型 @ 对应的专家 Agent        │
│  4. 编排执行：控制子 Agent 的调用顺序与依赖关系        │
│  5. 结果聚合：汇总各子 Agent 产出，统一呈现给用户      │
└───────────┬──────────────────────┬───────────────────┘
            │                      │
    ┌───────▼───────┐    ┌────────▼────────┐
    │ 子 Agent A    │    │ 子 Agent B      │
    │ (前端工程师)   │    │ (后端工程师)     │
    │               │    │                 │
    │ 生成页面代码   │    │ 生成 API 接口   │
    └───────┬───────┘    └────────┬────────┘
            │                      │
            ▼                      ▼
    ┌───────────────┐    ┌────────────────┐
    │ 代码 Diff 卡片 │    │ 代码 Diff 卡片  │
    │ 网页预览卡片   │    │ 部署状态卡片    │
    └───────────────┘    └────────────────┘
```

#### 群聊成员行为规范

| 角色 | 行为模式 |
|------|----------|
| **Orchestrator** | 始终可见，负责任务拆解与结果汇总，以系统消息形式展示任务分派状态 |
| **专家 Agent** | 被 @ 后激活，以独立气泡流式回复，回复结束后标记完成状态 |
| **用户** | 可在任意时刻介入，发送补充指令或修正方向，Orchestrator 会动态调整后续计划 |

#### 消息流呈现示例

```
👤 用户：帮我做一个带登录功能的 Todo 应用

🤖 Orchestrator：收到，我将任务拆解为以下步骤：
  ① 数据库设计 → @ 后端工程师
  ② API 开发   → @ 后端工程师
  ③ 前端页面   → @ 前端工程师
  ④ 联调部署   → @ DevOps 工程师

🔧 后端工程师：（流式输出中...）
  [代码 Diff 卡片] — User 表 Schema
  [代码 Diff 卡片] — Auth API

🎨 前端工程师：（流式输出中...）
  [代码 Diff 卡片] — Login 页面组件
  [网页预览卡片] — 实时渲染登录表单

🚀 DevOps 工程师：（流式输出中...）
  [部署状态卡片] — 部署中... ✅ 已完成
  预览链接：https://preview.agenthub.dev/abc123
```

### 2.3 上下文管理（Context Management）

#### 2.3.1 聊天历史

- **短期记忆**：每次对话的完整消息历史作为 Agent 的工作上下文，自动注入到每次请求中。
- **窗口策略**：当对话过长时，采用滑动窗口 + 摘要策略，保留最近 N 条消息的完整内容，更早的消息压缩为摘要。
- **Token 预算**：平台根据当前模型的上下文窗口大小，动态管理注入的历史消息量，确保不超出限制。

#### 2.3.2 Pin 消息机制

用户可手动将关键消息 "Pin"（置顶/固定），Pin 的消息将作为**长期上下文**永久注入后续请求，直到用户主动取消 Pin。

```
┌─────────────────────────────────────────────┐
│  📌 已 Pin 的消息（始终注入上下文）           │
│  ─────────────────────────────────────────── │
│  📌 "使用 Next.js 14 + Prisma + PostgreSQL" │
│  📌 "配色方案：深色主题，主色 #6366F1"        │
│  📌 "目标用户：开发者社区"                    │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│  💬 最近对话（滑动窗口）                      │
│  ─────────────────────────────────────────── │
│  👤 用户：把导航栏改成侧边栏                  │
│  🤖 Agent：好的，我来调整布局...              │
│  👤 用户：再加一个搜索功能                    │
│  🤖 Agent：收到，我来添加搜索组件...          │
└─────────────────────────────────────────────┘
```

#### Pin 操作交互

- 消息气泡悬停时显示 📌 图标，点击即可 Pin/UnPin。
- 对话顶部常驻 Pin 消息折叠栏，展开可查看所有 Pin 条目，支持拖拽排序和批量管理。

## 三、产物内联展示（Artifacts Inline）设计

### 3.1 设计理念

在 AgentHub 中，消息流**不只是文本**。每条 Agent 回复可以包含结构化的富媒体卡片，与文字说明混合排列在聊天流中。用户无需离开对话界面即可预览、操作、迭代所有产出物。

### 3.2 卡片类型总览

| 卡片类型 | 触发场景 | 核心能力 |
|----------|----------|----------|
| 代码 Diff 卡片 | Agent 生成或修改代码时 | 展示变更对比、一键 Apply、语法高亮 |
| 网页预览卡片 | Agent 生成前端页面/组件时 | iframe 沙箱实时渲染、响应式预览 |
| 部署状态卡片 | Agent 触发部署流程时 | 进度条展示、预览 URL 生成、一键跳转 |

### 3.3 代码 Diff 卡片

#### 数据结构

```typescript
interface CodeDiffArtifact {
  id: string;
  type: 'code_diff';
  filename: string;
  language: string;
  additions: number;
  deletions: number;
  hunks: DiffHunk[];
  status: 'pending' | 'applied' | 'rejected';
}

interface DiffHunk {
  oldStart: number;
  oldLines: number;
  newStart: number;
  newLines: number;
  content: string;
}
```

#### UI 呈现

```
┌─────────────────────────────────────────────────────────────┐
│  📄 src/components/Login.tsx                    [+42 -8]    │
│  ───────────────────────────────────────────────────────────│
│  12   │  import { useState } from 'react';                 │
│  13 - │  // old login logic                                 │
│  13 + │  import { useAuth } from '@/hooks/useAuth';        │
│  14 + │  import { Button } from '@/components/ui/Button';   │
│  ...  │  (syntax highlighted diff view)                     │
│  ───────────────────────────────────────────────────────────│
│  [ ✅ Apply ]    [ ❌ Reject ]    [ 📋 Copy ]              │
└─────────────────────────────────────────────────────────────┘
```

#### 交互行为

- **Apply**：将 Diff 变更应用到项目文件中，卡片状态变为 `applied`，显示绿色对勾。
- **Reject**：拒绝变更，卡片状态变为 `rejected`，显示删除线。
- **Copy**：复制变更内容到剪贴板。
- **展开/折叠**：默认折叠长 Diff，点击展开查看完整变更。

### 3.4 网页预览卡片

#### 技术实现

通过 **iframe 沙箱** 实时渲染 HTML/前端组件，隔离主应用与预览内容，确保安全性。

```typescript
interface WebPreviewArtifact {
  id: string;
  type: 'web_preview';
  title: string;
  html: string;
  css: string;
  js: string;
  viewport: 'mobile' | 'tablet' | 'desktop';
  sandboxPermissions: string[];
}
```

#### UI 呈现

```
┌─────────────────────────────────────────────────────────────┐
│  🌐 网页预览 — Login Page                                   │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  ┌─────────────────────────────────────────────────┐  │  │
│  │  │           ┌──────────────┐                      │  │  │
│  │  │           │   Login      │                      │  │  │
│  │  │           │   ┌────────┐ │                      │  │  │
│  │  │           │   │ email  │ │    ← iframe 沙箱     │  │  │
│  │  │           │   └────────┘ │      实时渲染         │  │  │
│  │  │           │   ┌────────┐ │                      │  │  │
│  │  │           │   │password│ │                      │  │  │
│  │  │           │   └────────┘ │                      │  │  │
│  │  │           │  [ Sign In ] │                      │  │  │
│  │  │           └──────────────┘                      │  │  │
│  │  └─────────────────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────────────────┘  │
│  ───────────────────────────────────────────────────────────│
│  [ 📱 Mobile ]  [ 💻 Desktop ]  [ 🔗 Full Screen ]        │
└─────────────────────────────────────────────────────────────┘
```

#### 交互行为

- **响应式切换**：支持 Mobile / Tablet / Desktop 三种视口快速切换。
- **全屏预览**：点击 Full Screen 在新标签页中打开完整预览。
- **实时刷新**：当关联的代码 Diff 被 Apply 后，预览卡片自动刷新渲染最新版本。
- **DevTools 集成**：开发者模式下可打开 iframe 内置的控制台进行调试。

### 3.5 部署状态卡片

#### 状态机

```
[ queued ] → [ building ] → [ deploying ] → [ live ] ✅
                                    ↘ [ failed ] ❌
```

```typescript
interface DeployStatusArtifact {
  id: string;
  type: 'deploy_status';
  status: 'queued' | 'building' | 'deploying' | 'live' | 'failed';
  progress: number; // 0-100
  previewUrl: string | null;
  logs: DeployLogEntry[];
  startedAt: string;
  completedAt: string | null;
}

interface DeployLogEntry {
  timestamp: string;
  level: 'info' | 'warn' | 'error';
  message: string;
}
```

#### UI 呈现

```
┌─────────────────────────────────────────────────────────────┐
│  🚀 部署状态                                                 │
│  ───────────────────────────────────────────────────────────│
│  Status: Deploying ████████████░░░░░ 75%                    │
│  ───────────────────────────────────────────────────────────│
│  [14:32:01] ℹ️  Building project...                         │
│  [14:32:15] ℹ️  Optimizing assets...                        │
│  [14:32:28] ℹ️  Deploying to edge network...                │
│  ───────────────────────────────────────────────────────────│
│  [ 🔗 打开预览链接 ]    [ 📋 复制 URL ]                     │
└─────────────────────────────────────────────────────────────┘
```

#### 交互行为

- **实时进度**：进度条与日志通过 WebSocket 实时推送更新。
- **预览链接**：部署完成后自动生成唯一预览 URL，支持一键跳转和复制。
- **失败重试**：部署失败时显示错误日志，并提供 "重试" 按钮。
- **版本回滚**：历史部署记录可追溯，支持一键回滚到任意历史版本。

## 附录：术语表

| 术语 | 释义 |
|------|------|
| **Agent** | 具备特定专业能力的 AI 智能体，如前端工程师、后端工程师、UI 设计师等 |
| **Orchestrator** | 主编排器 Agent，负责理解用户意图、拆解任务、调度子 Agent |
| **Artifact** | Agent 在对话中产出的结构化内容，包括代码 Diff、网页预览、部署状态等 |
| **Pin** | 用户手动固定的消息，作为长期上下文注入后续对话 |
| **Inline** | 产物直接嵌入聊天流中展示，无需跳转外部页面 |
| **Sandbox** | 用于安全渲染用户网页内容的隔离环境（iframe） |
