# AgentHub — 技术架构设计

> 最后更新：2026-05-28

---

## 一、整体架构

### 1.1 Monorepo 分层

```
AgentHub/
├── frontend/     ← Next.js 14 + React 18 + Tailwind CSS
├── shared/       ← JSON Schema (SSOT) + 自动生成的类型
└── backend/      ← FastAPI + SQLAlchemy + PostgreSQL
```

**依赖关系**：`frontend/ → shared/ ← backend/`，前后端通过共享契约层通信。

### 1.2 技术栈选型

| 层 | 技术 | 选型理由 |
|---|---|---|
| 前端框架 | Next.js 14 (App Router) | SSR + RSC 支持，适合 IM 实时交互 |
| 前端样式 | Tailwind CSS + Shadcn UI | 原子化设计，高度可定制 |
| 后端框架 | FastAPI | 原生 async/await，WebSocket 支持成熟 |
| 数据库 | PostgreSQL 15+ | JSONB 支持富媒体卡片，ACID 事务 |
| 缓存 | Redis 7+ | 分布式锁、WS 连接状态、流式缓冲 |
| 契约层 | JSON Schema Draft-07 | 单源信任，自动代码生成 |
| AI SDK | Anthropic + OpenAI | 接入主流 LLM 平台 |
| Agent 协议 | MCP (Model Context Protocol) | 标准化工具调用协议 |

## 二、后端架构

### 2.1 分层结构

```
app/
├── main.py           ← FastAPI 入口 + CORS + 路由注册
├── core/             ← 基础设施（配置、数据库、Diff 引擎、MCP 管理）
├── models/           ← SQLAlchemy ORM 模型
├── schemas/          ← Pydantic 校验 Schema
├── routes/           ← REST API + WebSocket 端点
└── agents/           ← Agent 适配层 + 编排器
    ├── base_adapter.py    ← 抽象基类
    ├── registry.py        ← 适配器注册表
    ├── orchestrator.py    ← 多 Agent 编排器
    └── providers/         ← 具体适配器实现
```

### 2.2 核心设计模式

**适配器模式 (Adapter Pattern)**

所有 LLM 调用必须继承 `BaseAdapter`，通过注册表工厂实例化：

```python
class BaseAdapter(ABC):
    @abstractmethod
    async def stream_chat(self, messages: list[Message], **kwargs) -> AsyncGenerator[MessageChunk, None]: ...

ADAPTER_REGISTRY = {
    "claude_code": ClaudeCodeAdapter,
    "codex": CodexAdapter,
    "opencode": OpenCodeAdapter,
    "custom": CustomAdapter,
}
```

**编排器模式 (Orchestrator Pattern)**

多 Agent 协作通过 Orchestrator 统一调度：

```
用户消息 → Orchestrator.process()
  ├── 单 Agent → 直接委派
  └── 多 Agent → LLM 规划 → 顺序/并行执行 → 结果聚合
```

### 2.3 WebSocket 协议

双向通信协议定义在 `shared/schemas/ws_messages.json`，包含 8 种消息类型：

| 方向 | 类型 | 说明 |
|------|------|------|
| C→S | `ping` | 心跳检测 |
| C→S | `sendMessage` | 用户发送消息 |
| C→S | `triggerAction` | 触发操作（如 applyDiff） |
| S→C | `pong` | 心跳响应 |
| S→C | `agentStatus` | Agent 状态变更 |
| S→C | `messageChunk` | 流式消息片段 |
| S→C | `messageComplete` | 消息完成 |
| S→C | `error` | 错误通知 |

## 三、数据库设计

### 3.1 ER 关系

```
User ──1:N── Session ──1:N── Message
  │                            │
  └──1:N── AgentProfile        │
              │                │
              └──N:M───────────┘ (通过 session.agent_ids)
```

### 3.2 核心表

| 表 | 主键 | 关键字段 |
|---|---|---|
| `users` | UUID7 | username, email, avatar |
| `sessions` | UUID7 | user_id, title, type, agent_ids |
| `messages` | UUID7 | session_id, sender_type, sender_id, content, card_data |
| `agent_profiles` | UUID7 | user_id, name, role, adapter_type, agent_config |

## 四、前端架构

### 4.1 四栏布局

```
┌──────────┬──────────────┬──────────────────┬──────────────┐
│ Project  │  Context     │    Chat Area     │   Agent      │
│ Dock     │  Sidebar     │                  │   Sidebar    │
│ (w-16)   │  (可拖拽)    │    (核心画布)    │   (可拖拽)   │
│          │              │                  │              │
│ 项目图标 │ 文件树       │ ChatHeader       │ Agent 面板   │

│          │              │ InputBar         │              │
└──────────┴──────────────┴──────────────────┴──────────────┘
```

### 4.2 核心 Hook

| Hook | 职责 |
|------|------|
| `useProjectState` | 项目状态 + LocalStorage 持久化 |
| `useEditorTabs` | 多标签页管理 + Diff 注入 |
| `useTheme` | 明暗主题切换 + 系统跟随 |
